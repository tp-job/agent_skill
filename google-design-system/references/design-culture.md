## 9. Design Culture — วัฒนธรรมการออกแบบองค์กร

### ตัวชี้วัดของ Design Culture ที่ดี

- Engineers พูดถึง Design ด้วยคำศัพท์ที่เหมาะสม
- มีความสะดวกสบายจาก Top-Down และ Bottom-Up ในการเข้าใจว่า Design มีผลต่อ Product
- อิทธิพลของ Design มองเห็นได้จากภายนอก (เช่น Google Rebrand, Material Design)

### Google UX Community

- สร้าง Team เฉพาะสำหรับ UX Community & Culture เพื่อรักษาสุขภาพของ UX ทั่วองค์กร
- จำนวนคน UX ที่ Google เพิ่มขึ้นหลายเท่าในช่วง 5 ปี

### Designer Profile ที่ Google ต้องการ

- สนใจสร้าง Product แบบครบวงจร (Top-to-Bottom)
- เข้าใจว่า Function และ Form ต่างก็สำคัญ
- มี Rigor (ความเข้มงวด) และ Accountability (ความรับผิดชอบ)
- ตระหนักว่างานตัวเองอาจส่งผลต่อผู้คนนับร้อยล้าน

> _"ทีมที่ดีมักถามคำถามที่ถูกต้องในการ Review — ไม่ใช่ 'ดูสวยไหม?' แต่ 'นี่ตอบโจทย์ User Need ได้ดีที่สุดไหม?'"_

## 10. AI Terms สำหรับ UX Designers

Designer ต้องรู้ศัพท์เหล่านี้เพื่อทำงานกับ Engineers และออกแบบ Edge Case ได้ถูกต้อง:

|คำศัพท์|ความหมายสำหรับ Designer|
|---|---|
|**AI (Artificial Intelligence)**|ทำ Rule-based Decisions → "ถ้าฝน → แนะนำร่ม" ต้องออกแบบ Rule States|
|**Machine Learning (ML)**|เครื่องจักรเรียนจากตัวอย่าง ออกแบบสำหรับ Confidence Range ไม่ใช่ Binary|
|**ML Model**|ชุดฟังก์ชั่นทางคณิตศาสตร์ ≠ Algorithm (กว้างกว่า) ≠ Neural Network เสมอไป|
|**Algorithm**|ลำดับขั้นตอนที่แน่นอน ถ้าใช้คำนี้ต้องแน่ใจว่าไม่ได้หมายถึง ML Model|
|**Neural Network**|โครงข่ายฟังก์ชั่น จำลองสมอง Deep Learning = หลาย Layer|
|**Supervised Learning**|เรียนจาก Labeled Examples นับแสนชิ้น เช่น เรียน Traffic → ทำนาย Commute|

**UX Design + AI — จุดตัดที่สำคัญ:**

- ออกแบบ Error State เมื่อ Model ผิดพลาด
- ต้องสร้าง Trust → Transparency, Explainability
- เข้าใจ Limitations ของ AI → ออกแบบ Edge Case ได้

## 11. Designing for Good — ออกแบบเพื่อสังคม

**People + AI Research (PAIR):**

- เป้าหมาย: ทำให้ AI เป็นประโยชน์ต่อมนุษย์ทุกคน ไม่ใช่แค่ผู้เชี่ยวชาญ
- ศึกษาว่า Human และ AI ทำงานร่วมกันได้ดีที่สุดอย่างไร

**Machine Teaching:**

- ออกแบบ Interface สำหรับการสอนคอมพิวเตอร์
- ทำให้กระบวนการ Label Data เรียบง่าย เข้าถึงได้ และเที่ยงตรง

**Ethics in Design (จาก SPAN Conference):**

- นักออกแบบมีความรับผิดชอบต่อ Ethics, Privacy, และผลกระทบต่อสังคม
- "Serious Play" — ใช้ Sketching, Legos ในกระบวนการ Ideation

## 12. Design Review — วิธีประเมินงานออกแบบอย่างถูกต้อง

### คำถาม 5 มิติที่ต้องถามทุก Review

**ด้าน User Need:**

- Product นี้ตอบสนองความต้องการของ User อย่างแท้จริงไหม?
- เราออกแบบสำหรับ User จริง หรือ User ที่เราคิดว่าเป็น?

**ด้าน Clarity:**

- User รู้ว่าต้องทำอะไรต่อไป โดยไม่ต้องอธิบาย?
- ข้อความ (Copy) ชัดเจนและ Actionable ไหม?

**ด้าน Usability:**

- ทดสอบกับ User จริงแล้วหรือยัง?
- ทดสอบกับ User ที่มีข้อจำกัด (Accessibility) แล้วหรือยัง?

**ด้าน Design System:**

- สอดคล้องกับ Design System ไหม?
- ถ้าเบี่ยงออก — เบี่ยงเพราะอะไร? มี Intention ไหม?

**ด้านอารมณ์:**

- Product นี้ทำให้ User รู้สึกอย่างไร?
- ความรู้สึกนั้นสอดคล้องกับ Brand ไหม?

> _"การถามคำถามเหล่านี้ครั้งแรกในการ Review เหมือนการเหยียดกล้ามเนื้อที่ไม่ได้ใช้มานาน — เจ็บ แต่มันดีต่อร่างกาย"_

## 13. UX Writing & Content Design

### หลักการ UX Writing

- **Clear, Concise, Useful** — ทุกคำต้องมีเหตุผลที่อยู่ที่นั่น
- ใช้ Second person ("you") และ Active voice
- Action Labels ต้องอธิบาย Action ไม่ใช่ Component ("Send Message" ไม่ใช่ "Submit")
- Error Messages: **บอกว่าเกิดอะไรขึ้น + วิธีแก้ไข**
- หลีกเลี่ยง Jargon, Negative Framing, Legal-ese

### UX Writing สำหรับ AI Products

|หลักการ|ความหมาย|
|---|---|
|**Transparent**|บอกผู้ใช้ว่า AI กำลังทำอะไร|
|**Humble**|ยอมรับข้อจำกัดของ AI อย่างตรงไปตรงมา|
|**Actionable**|ให้ทางออกเมื่อ AI ไม่แน่ใจหรือผิดพลาด|

**UX Writing + Accessibility:**

- ภาษาที่เรียบง่ายและชัดเจน ช่วยผู้ใช้ทุกกลุ่ม
- Alt Text สำหรับ Screen Reader
- Error Message ที่ช่วยให้ User ฟื้นตัวได้ (Recoverable Errors)

## 14. Brand Building — การสร้างแบรนด์ที่แข็งแกร่ง

### หลักการสำคัญ

- แบรนด์ที่ดีสอดคล้องกันในทุก Touchpoint
- Typography, Color, Motion ทั้งหมดเป็น "ผู้แสดงแทน" แบรนด์
- สร้าง System ไม่ใช่แก้ทีละชิ้น

### Google Rebrand 2015 — บทเรียน

- Logo ใหม่ = เพียงจุดเริ่มต้น
- ต้องอัปเดต Lockup, Typography, Color System ทั้งหมด
- Scale = ความท้าทาย → ต้องสร้าง System ไม่ใช่แก้ทีละชิ้น

**แบรนด์ที่ดีต้องตอบคำถามว่า:**

> _"ผู้ใช้รู้สึกอะไรเมื่อเห็น Product ของเรา? รู้สึกนั้นตรงกับที่เราตั้งใจไหม?"_

## 15. Typography — การเลือกฟอนต์อย่างมีหลักการ

### ขั้นตอน Step-by-Step (จาก Google Design Typography Guide)

1. กำหนด **Context** — Digital/Print? Size? Duration?
2. พิจารณา **Legibility** — อ่านออกในทุก Context ที่จะใช้ไหม?
3. เลือก **Voice** — ฟอนต์นี้สื่อ Personality อะไร?
4. ตรวจสอบ **Language Support** — รองรับภาษาผู้ใช้ทั้งหมดไหม?
5. ทดสอบ **Pairing** — ถ้าใช้หลายฟอนต์ มัน Complement กันไหม?

**Google Fonts:**

- คอลเลกชัน Open-Source สำหรับ Designer ทุกคน → fonts.google.com
- มี Knowledge Section อธิบาย Variable Fonts, Optical Sizes
