# Slide design — slides that support the teaching

The **Draw** stage. Slides cue and support the teacher. They don't replace the teacher, and they aren't a document projected onto a wall.

**How to read the numbers.** The size, line and colour limits below come from practitioner guides. Only one claim in the sources (about slide titles) cites research, and it is marked. Treat every number as a default to check on the real screen, not as a law. Source keys (full list in [sources](sources.md)): **[ITG]** IT-Guides 2026 · **[NIU]** Northern Illinois University CITL · **[COM]** COMSIAM · **[KCT]** KCT Academy 2024 · **[TT]** Teachers Tech.

---

## 1. Content rules

| Rule | Detail | Source |
| --- | --- | --- |
| **One slide, one idea** | explain a process across several slides. Don't cram every step onto one | [ITG] [COM] [TT] [NIU] |
| **Short text** | 3–5 lines per slide; bullets of keywords, not sentences. Detail goes in the speaker notes | [ITG] |
| **More slides beat denser slides** | avoid text-dense slides | [NIU] |
| **Sentence headlines** | a title that states the point ("Sales rose for four months running") is recalled better than a bare label. This is the only claim in the sources backed by a citation (Alley et al., 2006) | [NIU] |
| **Chart titles state the finding** | "Sales rose four months in a row", not "Monthly sales" | [ITG] |
| **Don't read from the slide** | if you must read it, it belongs in a handout | [NIU] |

**BAD:**
> *Slide title:* Q2 results. *Body:* a paragraph about revised marketing strategy, promotions and new channels, plus a table.

**BETTER:**
> *Slide title:* Q2 sales rose because of three changes. *Body:* Online marketing · Promotions · New sales channel

## 2. Type

| Item | Recommendation | Source |
| --- | --- | --- |
| Families | **no more than two**, consistent across the deck | [ITG] [NIU] |
| Avoid | handwriting, ornate or specialty faces | [ITG] [COM] [NIU] |
| Thai faces named | Sarabun / TH Sarabun New, Prompt, Kanit, Anuphan, Noto Sans Thai | [ITG] [COM] |
| Latin faces named | Aptos, Arial, Calibri, Tahoma | [ITG] [COM] |
| Emphasis | bold, italic or colour. **Not underline**, because underlined text reads as a link | [NIU] |

**Size depends on the room.** The sources disagree, so choose by setting:

| Setting | Title | Body | Basis |
| --- | --- | --- | --- |
| Large room, projector | ≥ 36–40 pt | ≥ 32 pt | [NIU] |
| Meeting room or webinar | 32–44 pt | 22–32 pt | [ITG] [COM] |
| Phone or self-paced online | upper end of the range, or larger | larger than usual | [COM] |

**The test that overrides the table:** stand at the back row, or hold a phone at arm's length, and read a body line. If you have to lean in, it is too small.

**Thai text (assessment):** tone marks and vowels stack above and below the line, so check that none are clipped and open the line spacing until they aren't. Check where long Thai lines break, since Thai has no spaces between words.

## 3. Colour and contrast

| Rule | Detail | Source |
| --- | --- | --- |
| A small system | 2–3 colours [KCT], up to 3–4 [COM], with roles: main (titles, key elements), secondary (charts, buttons, emphasis), background | [ITG] |
| Strong contrast | light background with dark type, or dark background with light type. Both read well in a large room | [NIU] [COM] |
| Avoid | neon, saturated colours, patterned backgrounds, colours that change often, and low-contrast pairs such as yellow on white | [ITG] [COM] [NIU] |
| Over a photo | dim the photo or add an overlay so the text stays readable | [ITG] |

**Conflict:** [COM] advises against "dark throughout", while [NIU] accepts a dark background with light text. Either works if contrast is strong and the choice is consistent. Don't switch mid-deck.

**Verify contrast:** compute it, don't judge it by eye. WCAG 2.2 AA asks for 4.5:1 for body text and 3:1 for large text.

## 4. Images, icons and charts

| Rule | Source |
| --- | --- |
| High-resolution, relevant images, one style across the deck, no watermarks | [ITG] |
| Use graphics only when they support the content. [NIU] states that irrelevant graphics hinder learning, without giving a citation | [NIU] |
| Icons: one style (all line, or all solid), from the built-in Insert > Icons if available | [ITG] |
| Charts: pick the type for the data, remove unneeded data, use colour only on the point, label only the key values | [ITG] |
| **2-D charts, not 3-D** | [NIU] [ITG] |
| A picture every one or two slides keeps lessons lively (for younger learners especially) | [COM] |

---

## 5. Layout and consistency

| Rule | Detail | Source |
| --- | --- | --- |
| Whitespace | don't push text to the edges; leave space between the title and body | [ITG] |
| Alignment | titles in the same place on every slide; left-align text; use Align and Guides | [ITG] |
| Repeat | reuse colours, fonts, structure and logo position so the deck reads as one | [KCT] |
| **But don't overdo repetition** | vary layouts a little so slides aren't all identical | [KCT] [COM] |
| Slide Master | set fonts, colours and bullets once. It also keeps the built-in accessible reading order | [NIU] [TT] |
| Templates | adapt them (colours, fonts, remove clutter). Don't use one unchanged | [ITG] |
| Aspect ratio | choose 16:9 or 4:3 to match the screen, and check it | [ITG] |

---

## 6. Animation and sound

| Rule | Source |
| --- | --- |
| Use **Fade, Appear, Wipe, Morph**. Avoid Spin, Bounce, Flash | [ITG] [COM] |
| Use it to control reveal order and pacing, or to show steps | [COM] |
| No more than one or two animations per slide; the same type for similar content | [TT] |
| "When in doubt, do without." Simple transitions only | [NIU] |
| Add sound and music only when necessary | [NIU] |

Animation that doesn't help the learner understand is decoration. Remove it.

---

## 7. The three-second test

Before a slide is done, run all three:

1. **Point:** can I state this slide's point in one sentence? If not, it's two slides.
2. **Squint:** blur your eyes. Is one thing clearly first?
3. **Back row:** can the smallest text be read from the far end of the room?

---

## When not to apply

- **A deck read on its own** (sent to learners, not presented). It can hold more text, but it is then a document, so design it as one.
- **A slide whose job is to be dense**, such as a reference table the class works from. Keep it as a handout or a single deliberate exception.
- **An established brand template** that overrides colours and fonts. Keep the brand's, and apply the content rules and the three-second test.
