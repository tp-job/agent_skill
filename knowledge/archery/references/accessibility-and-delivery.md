# Accessibility and delivery — the **Release** stage

A deck is finished when everyone in the room can use it and it opens on the real machine.

**Provenance:** the accessibility list is from Northern Illinois University's guide, which draws on University of Washington's accessibility guidance. Presentation habits are from NIU. The pre-flight checklist merges IT-Guides, COMSIAM and NIU. The "how to check" column and the handout timing note are this skill's own.

---

## 1. Accessibility

| Do | How to check |
| --- | --- |
| **Use the built-in layouts.** They keep the reading order the same for sighted users and screen-reader users. Change layouts in the Slide Master, not by hand | look at the layout gallery; edit the master |
| **Give every slide a unique, specific title** so learners can navigate to what they need | scan the outline view |
| **Alt text on every meaningful image, chart and table.** Describe what it shows in detail; avoid too many purely decorative visuals | tab through and read alt text |
| **Captions on all video and audio.** A transcript is a useful extra, but captions let people follow in real time | play a video with the sound off |
| **Simple tables, no blank cells.** A screen reader may take a blank cell as the end of the table | look for empty cells |
| **Set the reading order** for text on each slide. The order text appears in may not be the order it's read in | open the Selection Pane and check the order (it runs bottom-up) |
| **Hyperlinks with descriptive text** instead of a raw URL | scan the links |
| **Run the built-in Accessibility Checker** on the finished deck, and fix what it reports | run it. The result is your evidence |
| **Offer a PDF** for learners with visual impairments | export it |

The checker doesn't find everything. It can't tell whether alt text is *good*. Read some alt text aloud, and check contrast yourself (WCAG 2.2 AA: 4.5:1 body text, 3:1 large text).

**Never write "accessible" in a hand-off note unless the checker has been run and its result recorded.**

## 2. Presenting

| Do | Why (source's reasoning) |
| --- | --- |
| **Stand to one side and face the audience.** Use **Presenter View** so notes show on your screen only | you address people, not the screen |
| **Don't read the slides aloud** | it can look as if you don't know the material |
| **Keep the lights on** and switch off only the lights directly over the screen | a dark room impedes note-taking |
| **Move a laser pointer slowly** (a big enough dot, moved deliberately) | fast movement is hard to follow |
| **Press B or W** for a black or white screen when you want attention or reflection | it removes the distraction of the slide |
| **Leave time to finish** | rushing looks disorganised and is hard to follow |
| **Rehearse at least once, with a timer** | it checks timing and flow |
| **Have someone check the deck** | errors are more obvious when projected |

## 3. Handouts

Four policies, and each suits a different aim (from NIU):

| When | Effect |
| --- | --- |
| **Before class** | learners prepare and arrive with questions |
| **During class** | a three-slides-per-page handout with lines for notes has learners take notes on the *details*, not copy the slides |
| **After class** | learners attend to the talk instead of reading ahead |
| **Never** | learners don't rely on the deck and stop paying attention |

Choose one on purpose. Also available: Notes Pages, and Outline View (the text of all slides, which can be edited into a handout).

---

## 4. Online and mobile delivery

Learners may be on a phone, tablet or laptop. The source's advice for online: **larger type, more images, stronger colour, shorter slides.** Online material should be *easier* to read than in-room material, and it needs to make sense without you in the room. If it won't, add notes or a handout. Compress images for slow connections.

---

## 5. Pre-flight checklist

Run on the machine that will present, if possible.

- [ ] The file opens, with fonts, videos, audio and links working
- [ ] Fonts: embedded, or a PDF backup exists (installed fonts differ between machines)
- [ ] Aspect ratio matches the screen (16:9 or 4:3)
- [ ] Cables and drivers are right, if using your own laptop
- [ ] Backups: **.pptx and PDF**, in the cloud and on a USB drive
- [ ] Accessibility Checker run, and its result recorded
- [ ] Spelling and word usage checked; the deck viewed in Slide Sorter for order, gaps and repetition
- [ ] Rehearsed once with a timer
- [ ] Any live tool (poll, write-on slide) tested, with a paper fallback
- [ ] Plan B named: what you do if the tech fails, and what you cut if time is short
- [ ] Copyright: sources cited, and images licensed for use

---

## When not to apply

- **A one-off conversation** at a whiteboard. This checklist is for a prepared deck.
- **A fully remote session where you control the environment.** The room and projector items drop out, but the file, accessibility and backup items stay.
